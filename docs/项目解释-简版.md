# KG_Scene_Retrieval 项目解释（简版）

## 1. 一句话先说清项目在做什么

这是一个面向 `nuScenes v1.0-mini` 的自动驾驶场景检索系统。

用户输入一句中文或英文场景描述后，系统会：

1. 解析出天气、时段、地点、对象等条件
2. 用知识图谱先筛一批候选 scene
3. 用 CLIP + Milvus 在这些 scene 里检索最相关的帧
4. 最终返回图片结果，或者围绕命中帧生成视频片段

当前最终只有两种检索模态：

- `text2image`
- `text2video`

要特别记住：

- Milvus 存的是帧级实体，不是视频实体
- 视频片段是应用层派生结果，不是直接检索出来的

---

## 2. 七层分层

### 第 1 层：原始数据层

就是 `nuScenes` 数据集本体。

主要包括：

- `scene.json`
- `sample.json`
- `sample_data.json`
- `sample_annotation.json`
- `instance.json`
- `category.json`
- `log.json`
- `samples/`
- `sweeps/`

核心关系：

```text
scene -> sample -> sample_data -> 图像文件
sample -> annotation -> instance -> category
```

---

### 第 2 层：场景整理层

核心文件：

- `src/kg_builder.py`

作用：

```text
把原始数据整理成 scene 级结构化卡片
```

每个 scene 会被整理出：

- 场景名
- 描述
- 天气
- 时段
- 地点类型
- 对象统计
- sample 数量

---

### 第 3 层：知识图谱层

核心文件：

- `src/kg_builder.py`

主要节点：

- `Scene`
- `Weather`
- `TimeOfDay`
- `Location`
- `Object`

主要关系：

- `Scene -[:WEATHER]-> Weather`
- `Scene -[:TIMEOFDAY]-> TimeOfDay`
- `Scene -[:LOCTYPE]-> Location`
- `Scene -[:CONTAINS]-> Object`

作用：

```text
先按结构化条件筛选候选 scene
```

Neo4j 在这里不是做相似度排序，而是做 scene 级条件过滤。

---

### 第 4 层：自然语言理解层

核心文件：

- `src/nlp_parser.py`

作用：

```text
把用户的人话拆成系统可用的结构化条件
```

例如：

```text
雨天夜晚十字路口有行人
```

会被拆成：

- `weather = rainy`
- `time = night`
- `location = intersection`
- `objects = ["pedestrian"]`

同时它也会判断语言，决定后面走中文还是英文 CLIP。

---

### 第 5 层：向量检索层

相关文件：

- `src/milvus_utils.py`
- `scripts/insert_image.py`
- `app.py`

作用：

```text
把文本和图片帧放到同一个向量空间里，
再找最相似的帧
```

关键点：

- 中文查询走 Chinese-CLIP
- 英文查询走 English-CLIP
- Milvus 里存的是帧向量

#### 补全元数据是什么意思

当前项目插入图片时，不只是存 `id + embedding`，还会补：

- `scene_token`
- `sample_token`
- `camera`
- `frame_path`
- `weather`
- `timeofday`
- `location`
- `obj_types`

这样一张图在 Milvus 里就不只是“向量”，还是一个可解释的业务实体。

---

### 第 6 层：检索编排层

核心文件：

- `app.py`

作用：

```text
把解析、KG 过滤、文本编码、Milvus 检索、元数据补全、
图片返回和视频生成串成一次完整检索流程
```

主链路：

```text
用户输入
-> parse_query
-> get_candidate_scene_tokens
-> encode_text_query
-> search_frame_hits
-> enrich_hit_record
-> 返回图片或视频
```

回退逻辑：

- 先尝试 Neo4j
- Neo4j 不可用时退到本地过滤
- 如果候选 scene 为空，再回退到全库向量检索

---

### 第 7 层：结果生成与展示层

核心文件：

- `app.py`

支撑文件：

- `config.py`
- `start.bat`

两种最终输出：

#### `text2image`

直接展示命中的图片帧和说明文字。

#### `text2video`

先找到命中帧，再围绕该帧收集邻近帧，最后生成视频片段。

所以视频不是直接检索出来的，而是：

```text
先检索帧，再生成视频
```

---

## 3. 几个最容易混淆的点

### 1. Neo4j 和 Milvus 分工不同

- Neo4j：按条件筛 scene
- Milvus：按相似度搜帧

### 2. 一个 scene 不满足条件，不代表直接全库检索

只有所有 scene 都没有留下来时，才会回退到全库搜索。

### 3. `MERGE` 的意思

```text
有就复用，没有就创建
```

### 4. `[:WEATHER]` 的意思

它表示关系类型。

例如：

```cypher
(scene)-[:WEATHER]->(clear)
```

通俗地说就是：

```text
这个 scene 的天气是 clear
```

---

## 4. 一句话总总结

这个项目的本质是：

```text
用知识图谱先做 scene 级条件过滤，
再用 CLIP + Milvus 做帧级语义检索，
最后把结果展示成图片或动态生成的视频片段。
```
