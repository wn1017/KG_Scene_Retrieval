# KG_Scene_Retrieval 项目解释（简版）

## 1. 先统一当前项目口径

先把这个项目现在真正做什么说清楚：

- 当前最终检索模态只有 `text2image` 和 `text2video`
- Milvus 里存的是帧级实体，不是视频级实体
- `text2video` 是先检索命中帧，再围绕命中帧生成视频片段
- Neo4j 负责 scene 级结构化过滤，不负责向量相似度排序
- 当前实际运行配置以 [config.py](/D:/KG_Scene_Retrieval/config.py) 为准，默认不是旧文档里那种 `v1.0-mini` 主口径，而是 `v1.0-trainval` 的相机子集 `trainval_camera_part06_part10`

所以，这个项目的本质可以压缩成一句话：

```text
用知识图谱先筛 scene，再用 CLIP + Milvus 搜 frame，最后返回图片或基于命中帧生成视频片段。
```

## 2. 系统主流程

用户输入一句中文或英文场景描述后，系统会：

1. 解析出天气、时段、地点、对象等结构化条件
2. 用知识图谱先筛一批候选 scene
3. 用 CLIP + Milvus 在这些 scene 中检索最相关的帧
4. 返回图片结果，或者围绕命中帧生成视频片段

主链路对应 [app.py](/D:/KG_Scene_Retrieval/app.py) 中的逻辑：

```text
query
-> parse_query
-> get_candidate_scene_tokens
-> encode_text_query
-> search_frame_hits
-> enrich_hit_record
-> text2image / text2video
```

## 3. 四个关键模块

### 1. 自然语言解析

核心文件：

- [src/nlp_parser.py](/D:/KG_Scene_Retrieval/src/nlp_parser.py)

作用：

- 识别中文还是英文
- 提取 `weather`、`time`、`location`、`objects`
- 决定后面走 English-CLIP 还是 Chinese-CLIP

例如：

```text
雨天夜晚十字路口有行人
```

会被拆成：

- `weather = rainy`
- `time = night`
- `location = intersection`
- `objects = ["pedestrian"]`

### 2. 知识图谱过滤

核心文件：

- [src/kg_builder.py](/D:/KG_Scene_Retrieval/src/kg_builder.py)

作用：

- 从 nuScenes metadata 整理 scene 级 record
- 推断天气、时段、地点类型
- 统计对象类别
- 写入 Neo4j
- 按结构化条件查询候选 `scene_token`

一句话理解：

```text
Neo4j 负责按条件筛 scene，不负责搜相似图片。
```

### 3. 向量检索

核心文件：

- [src/milvus_utils.py](/D:/KG_Scene_Retrieval/src/milvus_utils.py)
- [scripts/insert_image.py](/D:/KG_Scene_Retrieval/scripts/insert_image.py)

作用：

- 把图像帧编码成向量
- 写入 Milvus
- 在检索时返回最相似的帧

当前 Milvus 记录的不只是向量，还包括：

- `scene_token`
- `sample_token`
- `camera`
- `frame_path`
- `weather`
- `timeofday`
- `location`
- `obj_types`

### 4. 在线编排与展示

核心文件：

- [app.py](/D:/KG_Scene_Retrieval/app.py)

作用：

- 组装查询解析、KG 过滤、文本编码、Milvus 检索和结果补全
- 构建 Gradio 页面
- 生成 `text2image` 和 `text2video` 的最终输出

## 4. `text2image` 和 `text2video` 的区别

### `text2image`

直接返回命中的高相关帧图像和对应说明。

### `text2video`

先检索到命中帧，再：

1. 找到该帧所属的 `scene`
2. 锁定同一个 `camera`
3. 收集相邻连续帧
4. 动态拼接成可播放视频

所以一定要记住：

```text
视频不是 Milvus 直接检索出来的，而是应用层基于帧结果生成的。
```

## 5. 当前仓库更像什么

这个仓库不是只有一个 Web demo，它同时承担三种角色：

- 在线检索演示系统
- 离线数据准备与入库工具集
- benchmark / 论文实验平台

对应目录大致是：

- [app.py](/D:/KG_Scene_Retrieval/app.py)：在线系统入口
- [scripts/](/D:/KG_Scene_Retrieval/scripts)：离线脚本
- [benchmark/](/D:/KG_Scene_Retrieval/benchmark)：实验输入与结果
- [tests/](/D:/KG_Scene_Retrieval/tests)：测试

## 6. 一个最容易混淆的点

旧文档里会频繁提到 `nuScenes v1.0-mini`，那更接近早期讲解口径。

而当前真实运行配置是：

- `v1.0-trainval`
- 子集名：`trainval_camera_part06_part10`
- collection：`multimodal_search_trainval_camera_part06_part10`

理解和运行项目时，应该优先以 [config.py](/D:/KG_Scene_Retrieval/config.py) 为准。

## 7. 一句话总结

```text
这个项目本质上是一个“scene 级 KG 过滤 + frame 级 CLIP 检索 + 应用层视频派生”的自动驾驶场景检索系统。
```
